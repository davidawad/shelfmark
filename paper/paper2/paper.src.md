## Abstract

Library classifications such as LCC and DDC are maintained by editorial
staff, are partly closed, and were not built against a stated, measurable
objective. We
propose the opposite: a general classification that is *fitted*, under the
constraints that make a classification usable on a shelf, to the same
quantity that a benchmark of existing schemes ranks them by. The objective
is J = D + {{lambda}} N, where D is the normalized Dasgupta cost of the
class tree on a fixed similarity graph [@dasgupta2016] and N is an expected
navigation cost in bits with a per-level charge. Two constraints are hard:
every class is a contiguous run of one fixed shelf order (the
optimal-alphabetic-tree constraint of Hu and Tucker [@hu1971]), and new
works are filed by splitting leaf classes only, so that every existing
class keeps its code, label and parent. We describe a deterministic fitting
algorithm (average linkage, rotation local search, an exact
dynamic-programming collapse to {{min_children}}-{{max_children}} children
and at most {{max_depth}} levels, and order-preserving local search), state
the identifier-stability guarantee precisely, and tie each clause of it to a
test. On a corpus of {{n}} arXiv papers the fitted prototype has
{{classes}} hand-labelled classes and reaches cost {{own_cost}} in sample
(average linkage {{ref_corpus}}; arXiv's own categories {{arxiv_gold_cost}};
the best existing scheme reached through the same lexical classifier
{{best_p1_cost}}). Fitted on {{train_pct}}% and tested on the other
{{test_pct}}%, it scores {{ho_cost}}. Filing {{n_holdout}} library books as
new works created {{ins_new_classes}} classes and changed no existing
identifier. These numbers flatter the method: the held-out and holdout
filings use the same embedding as the graph, the scheme has seen only
arXiv, and labels for inserted classes are weak. We state those limits
plainly, release the scheme as CC0 open data, and ask whether a learned,
open, order-preserving classification can become a general one.

## 1. Introduction

### 1.1 Why a learned general classification

A general classification gives every work one address in one linear order.
That order serves two readers: the person browsing a shelf, who wants
related works next to each other, and the cataloguer or system that must
file each new work somewhere. The schemes libraries use for this, LCC and
DDC above all, were enumerated by hand and have been extended editorially
since DDC's first edition of 1876 [@comaromi1976; @hjorland2025] and LCC's
early twentieth-century schedules [@fraser2020]. LCC's
schedules are freely downloadable as PDF [@freelcc] and LC describes its
linked-data service as a public-domain data set [@idloc]; the copyright in
DDC is owned by OCLC [@deweyrights]. Open universal alternatives exist (the Basic Classification
[@bk], the Free Decimal Correspondence [@fdc], the Integrative Levels
Classification [@ilc2]), alongside open thesauri with a hierarchy such as
the UNESCO Thesaurus [@unesco] and EuroVoc [@eurovoc], but none is both deep and open with a full
crosswalk (research report 1 on this branch). None of them, open or closed,
was designed against a stated, measurable objective, so there is no way to
say whether one is better than another for a given collection except by
argument.

Paper 1 (`bench/results/2026-10-10`, `bench/results/2026-10-10-r2`)
measured {{n_paper1_schemes}} published schemes on one objective scale: the
Dasgupta cost of each scheme's class tree over a fixed kNN similarity graph
of {{n}} arXiv papers, with navigation statistics alongside. That benchmark
makes the converse question natural. If a scheme can be scored, can a
scheme be *fitted* to the score, under the constraints a library needs, and
how far does it get?

Data-driven classifications already exist at scale. The CWTS
publication-level classification clusters a citation network by a
modularity-type function at several resolutions [@waltman2012; @traag2019],
and OpenAlex Topics assigns works to citation-derived topics whose upper
levels are mapped from an existing journal classification [@priem2022;
@openalextopics]. Topic-taxonomy builders such as TaxoGen
[@zhang2018taxogen] and LLM-driven pipelines such as Chain-of-Layer and
TnT-LLM [@zeng2024chainoflayer; @wan2024tntllm] produce trees from text.
None of these optimizes a shelf order, and none gives identifiers a
guarantee under growth. Those two properties are what separates a
classification from a clustering for a library.

### 1.2 Why order preservation matters

A shelf, a call-number index, and a browse list are each one linear order.
A hierarchy is useful for them only if every class is a contiguous run of
that order, so that "go to class X" means "go to one place". A tree fitted
without this constraint can always be drawn in *some* leaf order, but a
search that freely regroups works across the order produces classes whose
works are not adjacent once the order is fixed. We therefore fix the shelf
order first and restrict every later step to trees whose leaf order is
that shelf order. This is the alphabetic-tree constraint of optimal
order-preserving codes and search trees [@hu1971; @knuth1971], as opposed
to the free leaf order of Huffman coding [@huffman1952].

### 1.3 Why identifier stability matters

Class codes are written into call numbers, spine labels, catalogue records,
crosswalks and links. A classification that is refitted from scratch each
year would renumber works that never moved, invalidating all of those. For
a learned scheme this is the decisive practical objection: an optimizer
will happily trade any existing code for a small gain in the objective. We
therefore separate *fitting* (done once, in batch) from *growth* (done
incrementally), and constrain growth so that existing identifiers are never
changed, only refined. TaxoExpan [@shen2020taxoexpan] inserts new nodes into
a frozen taxonomy, but we found no objective in the literature that trades
optimality against re-shelving (research report 2).

### 1.4 Contributions

1. An objective for a general classification that combines similarity
   coherence and navigation cost, with explicit shape constraints, computed
   by the same harness that scores published schemes (Section 2).
2. A deterministic, order-preserving fitting algorithm, with an exact
   dynamic program for the collapse of a binary tree to a bounded-shape
   class tree (Section 3).
3. An insertion procedure for new works with a precisely stated
   identifier-stability guarantee, checked on every run and by tests on real
   data (Section 4).
4. A hand-labelled prototype, `scheme:learned@2026-10-10`, released under
   CC0, and a benchmark against {{n_paper1_schemes}} published schemes
   in sample, through a lexical classifier, on a held-out split, and on a
   holdout of library books (Sections 5-6, 9).

## 2. Objective

Let G be a weighted similarity graph over n works, with edge weights
w_ij and total weight W. Here G is the published Paper 1 graph: the
{{model}} embedding [@reimers2019; @wang2020minilm; @minilmcard] of title
and abstract, cosine similarity minus the mean pair cosine, k = {{k}}
nearest neighbours, symmetrized by maximum ({{edges}} edges over n = {{n}}
works). A class tree T places each work in one leaf class; a virtual root
holds the top-level classes.

**Similarity term.** Works hang under their leaf class, so two works in one
class meet at that class and pay its size:

    D(T) = (1 / (n W)) * sum over edges (i, j) of w_ij * |items(lca_T(i, j))|

This is Dasgupta's cost [@dasgupta2016], normalized so that a flat tree
scores 1, and it is exactly the harness's `cost_norm`. Its complement is the
Moseley-Wang revenue [@moseley2023]. Exact minimization is hard; the
approximation and axiomatic literature [@charikar2016; @cohenaddad2017]
and continuous relaxations [@chami2020] concern binary trees without shape
or order constraints, which is why we start from average linkage and add
the constraints in later steps. The harness also reports
`skill = (1 - D) / (1 - D_ref)`, where D_ref is the cost of the
average-linkage tree on the same graph.

**Navigation term.** The fan-out of a class is its number of child classes,
or its number of works if it is a leaf class. Then

    N(T) = (1 / n) * sum over nodes v with fan-out > 1 of |items(v)| * (a + log2 fanout(v))

is the mean, over works, of the cost of descending from the root to the
work, charging `a` per menu level plus `log2` of the menu size, a
Hick-Hyman-style choice cost [@hick1952; @hyman1953]. It is the harness's
`nav_log_a{{a}}`. A balanced tree pays about log2 n bits plus `a` per level,
so `a` prices a level and the `log2` part penalizes fan-outs that do not
match the sizes below them. Without `a`, depth would be free; without the
log term, the cheapest tree would be flat.

**Objective and constraints.**

    J(T) = D(T) + lambda * N(T),   lambda = {{lambda}},  a = {{a}}

subject to: every class has {{min_children}}-{{max_children}} child classes,
at most {{max_depth}} class levels, leaf classes of at least {{min_leaf}}
works, and every class a contiguous run of one fixed shelf order with
siblings ordered along it. With these weights, one extra level for every
work is worth a {{lambda}} drop in D: {{lambda_pct}} of the corpus
scanned per related pair.

The two terms pull against each other. D falls with every split and is
smallest for a binary tree with one work per leaf; N charges `a` bits per
level to every work under it. The choice of lambda, `a` and the depth bound
is a modelling decision, not a fitted quantity; Section 6.5 reports a sweep.
We do not claim that J is *the* objective for a general classification:
the optimal tree is defined relative to the similarity w, and there are
formal reasons to doubt any similarity-free optimum [@kleinberg2002;
@carlsson2010]. The claim is narrower: once a benchmark ranks schemes by D
and N, a scheme can be fitted to them, and the result is a reference point
for every hand-built scheme on the same scale.

## 3. Algorithm

`learned-scheme build` (`schemes/learned/src/fit.rs`) is deterministic for a
fixed seed ({{seed}}, used only for local-search visiting orders).

1. **Average linkage on the sparse graph** (`src/binary.rs`). Cluster
   similarity is the summed edge weight over the product of the cluster
   sizes, missing pairs counting 0; this is Moseley and Wang's average
   linkage, which approximates the optimal Dasgupta revenue within a factor
   of 1/3 [@moseley2023]. Ties go to the lowest cluster ids; disconnected
   components are joined smallest first. The resulting binary tree's cost,
   {{al_D}}, equals the harness's reference value.
2. **Rotation local search** on D. At a node x = (A, C) with A = (A1, A2),
   try ((A1, C), A2) and ((A2, C), A1) with exact local deltas. On this
   graph it makes {{rotations}} moves. That is expected: a rotation helps
   exactly when the average weight between A1 and C exceeds that between
   A1 and A2, and average linkage is reducible, so when A1 and A2 merged no
   part of a later C was closer. The pass certifies rotation-optimality and
   matters for other starting trees.
3. **Shelf order.** Each merge's two children are oriented so that the child
   more strongly tied to the works already shelved to its left comes first.
   The binary tree's leaf order becomes the fixed shelf order; nothing later
   changes it.
4. **Exact collapse** (`src/collapse.rs`). A dynamic program over the binary
   tree chooses which binary nodes become classes, contracting the rest, to
   minimize J over all such class trees within the shape bounds. For a class
   u it chooses the frontier of descendant classes by a knapsack over the
   binary nodes in between. Binary subtrees with fewer than {{min_leaf}}
   works are glued to their sibling and join the adjacent leaf class on the
   shelf. The DP is exact when nothing is glued above leaf level and close
   otherwise (J {{col_dp_J}} by the DP, {{col_J}} evaluated exactly here).
   Every tree this step can produce is order-preserving by construction,
   because contracting binary nodes never reorders leaves.
5. **Order-preserving local search** (`src/search.rs`) on exact J: shift a
   boundary work into the neighbouring leaf class on the shelf (incremental
   delta), hand the last child class to the next sibling or the reverse,
   merge adjacent sibling leaves, flatten a class into its parent, group two
   or three adjacent siblings under a new class. Every move keeps the shape
   bounds and the shelf order. Rounds repeat until no move improves J.

## 4. Identifier stability under insertion

### 4.1 Procedure

`learned-scheme insert` (`src/insert.rs`) files new works one at a time
without renaming anything.

1. A new work goes to the leaf class whose centroid is nearest (cosine on
   unit {{model}} vectors; the committed centroids are {{dims}}-dimensional,
   i8-quantized, one per leaf class with its work count).
2. A leaf class tries a two-means split, anchored on its fitted centroid,
   when either (a) it has taken at least {{ins_split_after}} new works and
   they form a distinct group (the two centroids' cosine is at most
   {{ins_max_cos}}), or (b) its new works reach its capacity: its fitted
   size, or the median fitted leaf size ({{leaf_median}}) for a class created
   by insertion. Capacity splits start from the first principal direction of
   the new works [@boley1998]. Both sides need at least {{ins_min_child}}
   works.
3. A split turns leaf C into the parent of two new classes: `C.01`, which
   keeps the core (C's earlier works and the new works near them) and is
   labelled "<C's label> (general)", and `C.02`, which takes the other group
   and is labelled from its works' most frequent title words.

### 4.2 Guarantee

Let S be a scheme and S' the scheme after inserting any sequence of works.
Then:

- **(G1) Existing classes are unchanged.** Every class of S is in S' with
  the same code, label, vocabulary, note and parent, and the classes of S
  appear in S' in the same relative order.
- **(G2) Only leaves are refined.** Every class of S' that is not in S has a
  parent, that parent was a leaf class of S or is itself a class created by
  insertion, and the new class's code extends its parent's code
  (`C` to `C.01`, `C.02`).
- **(G3) Existing works only move down.** A work filed in class C of S is in
  C or in a descendant of C in S'; when C is split, its earlier works go to
  `C.01`.
- **(G4) Shelf positions of existing works are kept.** Because `C.01` opens
  C's run and `C.02` follows it, a work that was in C keeps its position
  relative to every work of S.

G1 and the parent clause of G2 are what `insert::check_stable` checks;
`learned-scheme insert` runs it on every insertion and writes no output
scheme if it fails. The test `holdout_insertion_keeps_every_existing_id_and_parent_link`
(`schemes/learned/tests/insertion.rs`) inserts the {{n_holdout}}-book
holdout and checks G1 class by class (code, parent, label, vocabulary,
relative order), G2 including the code-extension clause, that exactly two
classes appear per split, that every new work sits in a current leaf class,
and the G3 clause that a split leaf's earlier works move only to a
descendant. `insertion_is_deterministic` checks that the same inputs give
byte-identical output, and `stability_check_rejects_changes_to_existing_classes`
(`tests/insert_rules.rs`) checks that `check_stable` rejects a relabelled
class, a new class under an existing internal class, and a reordering. G4 follows from the code grammar and the core-first construction; it
is not separately tested beyond G3.

The consequence for a catalogue: S' is a conservative extension of S. Its
codes and parent links are a superset of S's, an existing call number stays
valid (it may become less specific than it could be, never wrong), and
the inserted scheme takes the version `<version>.ins<count>`, so a client
that compares versions sees only the split leaves as changed.

What the guarantee does *not* say: it bounds nothing about J after
insertion, it does not keep the depth bound (a leaf can be split
repeatedly), and it says nothing about label quality for the new classes.
Section 8 returns to each of these.

## 5. Labels

No language model and no API was used. The {{classes}} fitted classes were
labelled by hand, by the AI coding assistant that built the prototype,
from a label sheet (`learned-scheme build --sheet`). For every class the
sheet shows its size, its top c-TF-IDF terms, and its most central titles
(largest summed graph weight to the class's other works). c-TF-IDF
is class-based TF-IDF as in BERTopic [@grootendorst2022]: tf(t, c) /
tokens(c) * ln(1 + A / f(t)) over titles counted twice and abstracts,
unigrams and adjacent bigrams, keeping terms present in a minimum share of
the class's works (`src/terms.rs`). The top terms also become the class's vocabulary in the
scheme file (source `ctfidf`), which is how shelfmark's lexical classifier
reaches the class.

Each label line in `schemes/learned/labels.tsv` stores the class's top
terms as a fingerprint, and the builder refuses a label whose
fingerprint no longer matches, so a refit that moves classes cannot keep
stale labels silently. `committed_scheme_is_valid_and_every_label_is_hand_written`
checks that no class of the committed scheme carries an automatic label.
Classes created by insertion get automatic labels (Section 4.1), and the
{{train_pct}}% fit used for the held-out split uses automatic labels
throughout.

We note the distinction from LLM taxonomy pipelines [@zeng2024chainoflayer;
@wan2024tntllm]: there the model proposes the structure; here the structure
is fixed by the objective and labelling is a separate, auditable step.
Whether hand labels written this way are good labels is a question for
human evaluation that this draft does not answer (Section 8).

**A cost that sees false joins.** Dasgupta cost charges for separating
similar works and nothing for joining dissimilar ones. A blind LLM judge of
librarian-style pair decisions agrees with the cost's flag at Cohen's
$\kappa$ = {{x_val_kappa}} on {{x_val_n}} pairs [@cohen1960]; adding a
false-join term raises that to {{x_val_kappa_fj}} (Paper 1, Sections 3.7
and 5.6 to 5.7). For a seeded sample of non-edge pairs whose cosine is
below the graph's mean pair cosine $\tau$, weighted by $d = \tau - \cos$,
the specificity form is
$\mathrm{FJs} = \sum d \ln(n/N(\mathrm{lca})) / (\ln n \sum d)$ and the
outside-mass form is $\mathrm{FJ} = \sum d\,(n - N(\mathrm{lca})) / (n \sum d)$,
one minus the normalised dissimilarity objective of Cohen-Addad et al.
[@cohenaddad2017]. The corrected objective is
$J' = C + \mathrm{FJs} + 0.002\,N$. Its weight on N is Paper 1's, not the
{{lambda}} the scheme was fitted with. For the learned scheme placed by the
lexical classifier, the judge's agreement does not change with the term
($\kappa$ {{x_val_learned_k0}} to {{x_val_learned_k1}}, change
{{x_val_learned_dk}} [{{x_val_learned_dk_lo}}, {{x_val_learned_dk_hi}}]):
the judge rarely finds a false join in it.

On arXiv papers it also survives the false-join correction. On library
books, which it was not fitted to, it does not survive: under the corrected
objective its lead over librarian-assigned Dewey and LCC numbers depends on
the graph setting, and under the outside-mass form it is usually behind.

## 7. Discussion

**What the prototype shows.** Under a stated objective, a fitted
order-preserving scheme with {{classes}} hand-labelled classes scores well
below every published scheme on that objective with its own placements, in
sample and on a held-out split. Through the same lexical classifier as the
published schemes it is still below every published scheme's placed row
({{lp_cost}} against {{best_p1_cost}} for the best), but above arXiv's own
author-chosen categories ({{arxiv_gold_cost}}). Most of that gap is expected: the published schemes were not built
for this corpus or this similarity, and several are domain schemes on
foreign ground. The useful result is not the ranking but the reference
point. A hand-built scheme can now be described as "this far from a fitted
scheme with the same number of levels on the same graph", and the cost of
each constraint (order preservation, the depth bound, stable insertion) can
be measured rather than argued.

**The price of order preservation is not yet measured.** The DP collapse
and the local search work only within one fixed shelf order, and the
fitted tree keeps {{own_skill_pct}} of the average-linkage revenue. That
loss mixes two effects: collapsing a binary tree to a bounded-shape class
tree, and doing so without reordering works. Any binary tree has a
compatible leaf order, so the order constraint costs nothing before the
collapse; whether it costs much after it needs a bounded-shape fit without
the order constraint, which we have not run. Whether the answer holds for a
heterogeneous collection is open.

**Stability as a design constraint.** Separating batch fitting from
incremental growth gives a guarantee a cataloguer can rely on (Section 4.2)
at the price of drift: the inserted scheme is no longer J-optimal and its
depth grows where new material concentrates. A periodic refit would restore
optimality but break identifiers. A principled middle ground, an objective
that charges for every renumbered work, is the open problem we would most
like to see addressed (research report 2 found no prior formulation).

**Towards a general classification.** A general scheme needs a general
corpus. The corpus here is papers from arXiv's top-level archives; a library's
collection is mostly books, much of it in the humanities, arts and social
sciences, with titles and subject headings rather than abstracts. The
method transfers (it needs only a similarity graph and text for labels);
the scheme does not, as the holdout shows.

## 8. Limitations

### 8.1 Embedding circularity flatters the held-out and holdout numbers

The graph is built from {{model}} embeddings, and insertion files a new
work at the nearest leaf centroid in the *same* embedding space. A new work
is therefore placed by exactly the geometry it is later scored on. This is
the circularity the benchmark design warns about (DESIGN.md, finding 6) and
it favours the learned rows in Tables 4 and 6. It is worst on the holdout,
where both the graph and the insertion see only title embeddings. The
published schemes' placed rows, and the learned scheme's own placed rows,
use the lexical classifier and do not share this advantage. A fair test
needs a second, independent similarity (another embedding model, citation
coupling, or subject-heading overlap; DESIGN.md section 2.2), which this
draft does not have.

### 8.2 Fitted on arXiv only

The scheme has seen only arXiv papers. Its top level splits computing from
mathematics and the physical sciences; it has no class for the humanities,
law, arts or literature until insertion creates one, and then a weak one.
It is a general *method*, not yet a general classification. The arXiv
sample itself is proportional to archive size with a floor per archive
(`bench/corpus/README.md`), and computer science is its largest part:
{{cs_share}} of the papers have a `cs` primary category.

### 8.3 A binary root under this objective

The root has {{root_children}} children in the committed scheme and in
{{sweep_binary_root}} of {{sweep_fits}} sweep fits. Dasgupta cost prefers a
binary split near the top, where most cross-cluster weight sits, and the
navigation term charges only per level, so it cannot prefer a wide first
menu. Library schemes have wide top levels (LCC's first level is its set of
lettered main classes [@freelcc]) for reasons of browsing and memorability that J does not model.
A top-level fan-out prior, or a navigation cost with a linear scan term
(the harness's `nav_scan`), may change this; we have not tested either.

### 8.4 Weak automatic labels for inserted classes

Classes created by insertion are labelled from their works' most frequent
title words. Table 7 shows the result: labels such as
"{{ins_first_new_label}}" for the first class of books, and a chain
of "(general)" core classes that repeat their parent's label down
{{ins_max_class_depth}} levels. These are not usable as catalogue captions.
The hand labels for fitted classes were written by an AI coding assistant
from the label sheet, not by a cataloguer, and have not been evaluated by
people, nor scored with any of the taxonomy-quality attributes in the
literature [@unterkalmsteiner2023].

### 8.5 Classifier coverage on book titles

The class vocabulary is mined from arXiv titles and abstracts, so
shelfmark's lexical classifier rarely matches book titles: {{hlp_placed}} of
{{n_holdout}} holdout books ({{hlp_cov}}) were placed. The non-circular
comparison on books (Section 8.1) is therefore uninformative for this
scheme until its vocabulary covers books.

### 8.6 Graph-hash non-reproducibility with near-tied edges

Rebuilding the published graphs from the pinned embedding weights
(`model.onnx` sha256 `{{model_sha}}...`) on a different ONNX Runtime
version gives edge weights that differ by floating-point noise and, in a
few places, a different choice between near-tied nearest neighbours; the
rebuilt graph's hash therefore differs from the published one
(`bench/results/2026-10-10-learned/REPRODUCE.md`). The fit uses only the
published graph, so the scheme rebuilds byte for byte, but anyone
regenerating the graph from text will get a slightly different graph and
possibly a slightly different scheme. The vectors enter insertion only
through i8-quantized centroids, whose quantization step is coarser than the
noise. The graph file, not the embedding pipeline, is the reproducible
artefact.

### 8.7 Other limits

- Insertion does not keep the depth bound: holdout insertion produced
  classes {{ins_max_class_depth}} levels deep and a mean work depth of
  {{h_mean_depth}} in the harness's tree (Table 6).
- One corpus, one graph, one objective weighting. This paper reports no
  bootstrap intervals or permutation nulls for the learned rows (DESIGN.md
  section 2.5 proposes both). Item-bootstrap intervals for the learned runs
  are in `bench/results/2026-10-10-covered` and `-embed`, and a permutation
  null has not been run.
- No user study: N is a model of navigation cost [@hick1952; @hyman1953],
  not a measurement. User studies of menu depth and breadth disagree on
  the best shape: speed and accuracy improved with breadth in one
  [@snowberry1983], others found an optimum at moderate breadth
  [@miller1981; @larson1998], and none of these was run on a library
  classification, so they do not calibrate N.
- The comparison mixes gold rows (a source's own labels), placed rows (a
  classifier's output) and own rows (fitted or inserted); they answer
  different questions and should not be read as one ranking.

## 9. Release as CC0 open data

`schemes/learned/learned.json` (`scheme:learned@2026-10-10`, sha256
`{{scheme_sha}}...`), its hand-written labels (`labels.tsv`), and the leaf
centroids and quantized holdout vectors in `schemes/learned/data/` are
dedicated to the public domain under CC0 1.0 [@cc0]. The builder code is
MIT OR Apache-2.0 like the rest of the repository. CC0 is chosen so that the
scheme, unlike DDC, can be copied into catalogues, crosswalks and derived
schemes without conditions, and so that it combines with other CC0 sources:
arXiv metadata [@arxivlicense] and Open Library's catalogue data, which
Open Library describes as dedicated to the public domain and asks
contributors to share under CC0 1.0 [@openlibraryfaq]. The scheme validates
against the repository's scheme schema
(`shelfmark scheme validate --path schemes/learned/learned.json`), and
`sources.lock.json` records the sha256 of every input. The scheme
identifiers are versioned (`learned@2026-10-10`, `{{ins_scheme}}`
for the holdout insertion), and the stability guarantee of Section 4 is
part of the release: a future version that grows by insertion keeps every
code of this one.

Repository location: not stated in this draft; it is to be given on release.

## 10. Reproducibility

- **Inputs.** Corpus, holdout, the published k = {{k}} graphs and the
  scheme are committed with their sha256 values; the graphs were built with
  {{model}} weights revision `{{model_rev}}`.
- **Fit.** `cargo run --release --manifest-path schemes/learned/Cargo.toml
  -- build ...` (commands in `schemes/learned/README.md`) rebuilds
  `learned.json` byte for byte from committed files in seconds; the test
  `rebuild_reproduces_the_committed_scheme_and_matches_the_harness` enforces
  this, and `sources_lock_and_registry_match_the_committed_files` checks the
  input hashes.
- **Benchmark.** `bench/results/2026-10-10-learned/REPRODUCE.md` gives every
  command, including the Paper 1 placement rerun, embedding the vectors for
  the centroids, and `crates/bench/scripts/learned_benchmark.py`. The
  results record the tool commit (`{{tools_commit}}`) and binary hashes.
- **Determinism.** The fit is seeded ({{seed}}) and single-threaded;
  insertion is deterministic (tested). The one non-reproducible step is
  regenerating the graph from text (Section 8.6).
- **This paper.** `python3 paper/paper2/scripts/make_tables.py` regenerates
  `paper.md` and `tables/` from the JSON; `--check` fails if they are stale.
  The script cross-checks J against its two terms for every row, the placed
  rows against the Paper 1 rerun, and the fit report against the harness.
