# UNESCO Thesaurus scheme (`unesco-thesaurus`)

`unesco-thesaurus.json` is scheme `unesco-thesaurus@2026-08-31`: the
[UNESCO Thesaurus](https://vocabularies.unesco.org/) (education, science,
culture, social and human sciences, information and communication,
politics, law and economics, countries) as a shelfmark scheme file. It
is generated by this crate (`unesco-thesaurus build`); do not edit it by
hand. The version is the thesaurus's own `dct:modified` date.

```sh
shelfmark scheme compile schemes/unesco-thesaurus/unesco-thesaurus.json   # preview, then --commit
```

## Rebuild

```sh
cargo run --release -- fetch --cache ~/.cache/unesco-thesaurus   # network; rewrites sources.lock.json
cargo run --release -- build --cache ~/.cache/unesco-thesaurus   # offline, deterministic from the lock
cargo run --release -- check --cache ~/.cache/unesco-thesaurus   # fails if the JSON is stale
```

The source is one SKOS Turtle export,
`https://vocabularies.unesco.org/exports/thesaurus/latest/unesco-thesaurus.ttl`
(about 4 MB). The URL always serves the latest version and UNESCO keeps
older ones "upon request" only, so `sources.lock.json` pins its sha256
and `build` refuses a cached file that differs. `build --fetch` downloads
the file when the cache lacks it; if UNESCO has published a newer
version the hash check fails, which is the cue to run `fetch` and
review the diff. The export is not committed.

## Hierarchy

Domain (7) > microthesaurus (88) > concept (4,500). Codes: the domain
and microthesaurus `skos:notation` (`1`, `1.05`) and `c<id>` for a
concept (`c460` is `:concept460`). Every concept belongs to exactly one
microthesaurus (the build checks it), so the first two levels partition
the concepts.

The thesaurus is polyhierarchical (229 concepts have 2 to 6 broader
terms) and the scheme format is a tree. The rule:

1. A concept's parent is its `skos:broader` term in the **same
   microthesaurus** with the lowest numeric id.
2. A concept with no broader term in its own microthesaurus (all 585
   top concepts, and the one concept whose broader terms are all
   elsewhere) hangs directly under its microthesaurus.
3. Every other broader term (429 links) is kept as a vocabulary link
   with source `unesco-broader`, weight 0.5, `source_id` the broader
   concept's id, and named in the class note ("Also narrower than: ...").
4. A cycle among broader terms fails the build.

Cross-microthesaurus broader links never move a concept out of its
microthesaurus.

## Labels and vocabulary

English only. Label: `skos:prefLabel@en`. Note: `skos:scopeNote@en`.
Vocabulary: `skos:altLabel@en` (source `unesco-alt`, weight 0.9, 2,932
terms), `skos:hiddenLabel@en` (`unesco-hidden`, 0.7, 4 terms) and the
demoted broader terms above. A term equal to the class label or to an
earlier term of the same class is dropped. `skos:related` is not used.
The thesaurus has no LCC or LCSH mappings.

## Tests

```sh
cargo test                                          # Turtle reader, synthetic export, committed file
UNESCO_THESAURUS_CACHE=~/.cache/unesco-thesaurus cargo test   # also rebuilds byte for byte
```

`tests/fixture.rs` builds a small synthetic export in UNESCO's format and
checks the schema, the compiler, the polyhierarchy rule, vocabulary and
the failure cases. `tests/real.rs` validates the committed file and, with
the cache, rebuilds it from the locked export (skipped otherwise;
`UNESCO_THESAURUS_REQUIRE_CACHE=1` turns the skip into a failure).
